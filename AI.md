# AI-Assisted Programming

This project was significantly enhanced using AI tools (Gemini and ChatGPT) to assist with feature implementation, architectural refactoring, complex debugging, and test automation.

## 1. Architectural Refactoring & Bug Fixing
**Goal:** Fix severe bugs related to UI rendering and output duplication.

* **Single Source of Truth (SSOT) Implementation:** The AI diagnosed a "double-printing" bug where the GUI and CLI terminal were both rendering output simultaneously. It guided the refactoring of `Nimbus.java` and `Ui.java` to enforce the UI buffer (`StringBuilder`) as the sole source of truth, silencing unwanted terminal prints.
* **Separation of Concerns:** Guided the migration away from string-returning `execute` methods in `Command` classes, forcing all output to be cleanly routed through a dedicated `ui.showMessage()` method.
* **Warning Suppression:** The AI provided a custom `PrintStream` interceptor for `Launcher.java` to gracefully filter out the unavoidable `Unsupported JavaFX configuration` unnamed-module warnings generated by Fat JAR compilation, ensuring a perfectly clean terminal startup experience.

## 2. Feature Implementation: Update Command (C-Update)
**Goal:** Implement a command to edit existing tasks and upgrade their types (e.g., converting a Todo to a Deadline).

* **Logic Design:** The AI proposed and refined the logic for `UpdateCommand.java`. This included a state-transition mechanism where providing a date (`/by`) to a Todo automatically converts it into a Deadline, and providing a range (`/from`, `/to`) converts it into an Event.
* **Dynamic Parsing:** The AI provided the logic for `Parser.java` to handle optional flags order-independently. It introduced string manipulation techniques to extract descriptions cleanly by calculating dynamic cut-off indexes based on the presence of `/by`, `/from`, or `/to` flags, preventing "dirty" descriptions where command flags were accidentally saved as text.

## 3. Code Quality & SLAP (Single Level of Abstraction Principle)
**Goal:** Improve readability, adhere to Modern Java standards, and ensure defensiveness.

* **Method Extraction:** The AI refactored the overloaded `getResponse` method in `Nimbus.java` by extracting storage operations into a dedicated `handleAutoSave()` method.
* **Reducing Nesting (Arrowhead Anti-Pattern):** The initial implementation of `UpdateCommand.execute` had deep `if-else` nesting. The AI refactored this into flat helper methods (`createNewDeadline`, `createNewEvent`, etc.), improving readability and maintainability.
* **Modern Java Syntax:** The AI identified warnings related to explicit casting and suggested using **Pattern Matching for `instanceof`** (e.g., `if (original instanceof Event oldEvent)`), which made the code cleaner and resolved IDE warnings.

## 4. Test Automation (JUnit)
**Goal:** Ensure robustness of the logic and satisfy grading requirements.

* **Targeted Test Generation:** The AI generated standard-compliant JUnit tests for `TaskListTest.java` and `ParserTest.java`, focusing on boundary conditions and custom exception handling (e.g., verifying `NimbusException` is thrown for empty descriptions or invalid indexes).
* **Stubbing for GUI:** The AI demonstrated how to create a `TestUi` stub class in JUnit to verify `String` return values, allowing logic to be tested without launching the actual JavaFX application.
* **Regression Testing:** The AI suggested specific test cases to prevent regression, such as verifying that updating a description *without* flags does not accidentally wipe out existing dates for Deadlines or Events.

## 5. Tools Used
* **Gemini:** Primary tool for deep architectural refactoring (such as the SSOT UI buffer implementation), complex GUI/CLI debugging, generating targeted JUnit tests, and drafting comprehensive project documentation.
* **ChatGPT:** Utilized alongside Gemini to assist with initial logic generation, rapid syntax troubleshooting, and refining the parser and command execution flows for features like the `UpdateCommand`.
